# Гибкое чтение подписок и отпечаток клиента в админке

Статус: **проектирование, кода нет**. Ветка `feature/flexible-subs-and-fingerprint`.

Задача: научить podkop-subscriptions читать подписки разных форматов и дать
задавать отпечаток клиента (заголовки запроса) статично через LuCI, вместо
зашитых в код констант. Источник приёмов — `universal-sub-proxy-v2`
(`server.js`, 797 строк), разобранный в
`/root/projects/giminitest/gemini-node-filter/docs/sub-proxy-v2-logic.md`.
Живой исходник лежит локально:
`/root/projects/giminitest/backups/debiandell/2026-09-04_02-17-58/sources/universal-sub-proxy-v2/server.js`.

Проект `gemini-node-filter` к задаче отношения не имеет и не трогается.
Ручка `/capture` и сервис-catcher не переносятся: отпечаток вбивается руками.

## 1. Что уже есть в updater

Разобрано по коду, всё в `podkop-sub-updater.py`:

| Что | Где | Состояние |
|---|---|---|
| Отпечаток клиента | строки 36–42 | **есть, но зашит константами**: `SUBSCRIPTION_USER_AGENT`, `_DEVICE_OS`, `_VER_OS`, `_DEVICE_MODEL`, `_APP_VERSION`, `SUBSCRIPTION_HWID` |
| Отправка заголовков | `read_source_payload`, ~767 | `wget -qO-` с шестью `--header`, порядок и регистр фиксированы кодом |
| Разбор ответа | `extract_links_from_payload`, 822–844 | только два формата: plain и base64 |
| Протоколы | `VALID_PROTOCOLS`, 44 | vless, ss, trojan, socks4/4a/5, hy2, hysteria2 |

То есть по классификации из разбора v2 проект сейчас находится на стадии
`header-proxy`: заголовки зашиты, меняются только пересборкой.

## 2. Отпечаток: как выносить в админку

**Хранение.** Новая секция UCI в `/etc/config/podkop_subscriptions`, рядом с
`subscription_group` и `subscription_schedule`:

```
config fingerprint 'v2raytun'
    option enabled '1'
    option headers '<многострочный блок>'
```

Заголовки одним многострочным полем, а не набором `option user_agent` и
т.п. Причина: панель может смотреть на регистр (`X-HWID` против `x-hwid`) и
на порядок следования, а список отдельных опций и то и другое теряет.
Многострочный блок сохраняет оба свойства сам собой и совпадает по виду с
тем, что отдаёт `/headers` старого catcher-а, то есть вставляется копипастой:

```
User-agent: v2raytun/android
X-HWID: <HWID-REDACTED>
X-Device-OS: Android
X-Ver-OS: Android 11
X-Device-Model: OnePlus MT2110
X-App-Version: 5.25.81
```

**Привязка.** У `subscription_group` появляется `option fingerprint 'v2raytun'`.
Пусто означает поведение как сейчас, на зашитых константах, поэтому
существующие конфиги продолжают работать без правки.

**LuCI.** Textarea в панели (`luci/www/luci-static/resources/view/podkop_subscriptions/`).
Помнить про кеш браузера: панель уже ловила проблему, когда старый
`content.js` продолжал исполняться, поэтому файл ставится под версионным
именем.

**Секретность.** `X-HWID` идентифицирует устройство, панель по нему опознаёт
клиента. В лог и в отчёт он попадать не должен: логируется только имя
профиля. Правило то же, что уже действует для URL подписок.

## 3. Транспорт: остаёмся на wget

Оригинал v2 ходит внешним `curl`, потому что Node переписывает заголовки.
У нас этой проблемы нет: `subprocess` + `wget --header` уже используется в
`read_source_payload` и на реальных панелях работает. Ставить на роутер
`curl` незачем.

Питоновский `http.client` (вариант из первоначального дизайна под Docker)
на роутере **не годится**: стандартный `ssl` в OpenWrt лежит в отдельном
пакете `python3-openssl`, а проект сознательно держится на голом
`python3-light` (см. комментарий в `podkop-sub-updater.py:341`).

Две правки по ходу дела:

* сейчас User-Agent уходит дважды, и через `--user-agent=`, и через
  `--header 'User-Agent: …'`; оставить одно;
* `Accept-Encoding` не добавлять. v2 его снимает ради `curl --compressed`, а
  у нас `wget -qO-` читается как текст, и сжатый ответ превратится в мусор.

## 4. Разбор: что добавляем

По убыванию отношения пользы к объёму.

1. **Детект заглушки** (`looksLikeBlockedBody`, ~10 строк). Первые 1500 байт:
   пустое тело, `403.html`, `DDoS-Mitigation` рядом с `iframe`, `<html`
   рядом с `403`. Ценность в том, что это главный симптом протухшего
   отпечатка, а панели отдают такие заглушки с кодом 200, то есть сейчас они
   молча превращаются в «0 ссылок».
2. **Аккуратный base64** (~15 строк). Сейчас `extract_links_from_payload`
   пытается декодировать что угодно, если не нашёл plain-ссылок, и не знает
   url-safe алфавита (`-`, `_`). Забрать из v2 `looksLikeBase64`: нет `://`,
   длина ≥ 8, длина % 4 ≠ 1, алфавит с `-_`; и принимать результат, только
   если внутри появился `://` либо это похоже на JSON.
3. **JSON-конфиги Xray и sing-box** (~290 строк, строки 282–570 оригинала).
   Самая объёмная часть. Диалекты различаются наличием `protocol` у
   outbound: есть — Xray (`settings.vnext[]`, `streamSettings`), нет, но
   есть `type` — sing-box (плоские `server`, `server_port`, `transport`).
   Можно урезать до vless/trojan/ss и добрать остальное по необходимости.
4. **Clash/Mihomo YAML** — **не берём**. Нужен `python3-yaml` отдельным
   пакетом, это нарушает принцип «только python3-light». Ручной разбор
   `proxies:` слишком хрупок, чтобы того стоить.

Порядок разбора менять на v2-шный: **base64 → прямые URI → JSON**. Текущий
«plain, иначе base64» ломается на подписке, которая является base64 от JSON.

Всё несконвертированное копится с причиной и уходит в лог, а не теряется
молча (у v2 это `stats.unsupported`, до 50 записей).

**Разворачивание доменов в IP** (`expandDomainIps` у v2) сюда не переносим:
в podkop список узлов и так подрезается по `max_links` и `max_latency_ms`,
и умножение записей на число A-записей будет с этим воевать.

## 5. Бюджет

| Что | Прибавка |
|---|---|
| Новые пакеты opkg | **ноль** (при отказе от Clash/YAML и сохранении wget) |
| Место на роутере | только размер самого `.py` |
| Код | +40 строк на пункты 1–2, +290 на пункт 3 при полном переносе |
| `podkop-sub-updater.py` | сейчас ~124 КБ; пункт 3 это примерно +10% |

То есть «разжиреет» только один пункт, третий, и он же единственный, который
можно безболезненно урезать или отложить.

## 6. Порядок работ

1. Отпечаток: секция UCI, чтение в updater, привязка к `subscription_group`,
   textarea в LuCI. Обратная совместимость через пустое значение.
2. Пункты 1–2 из раздела 4 (заглушка и base64). Малый объём, сразу польза.
3. JSON-диалекты, если понадобятся на реальных подписках.
4. README/README_RU и CHANGELOG.

## 7. Открытые вопросы

* Сколько профилей отпечатка нужно на практике: один общий или по одному на
  подписку. Схема выше допускает несколько, но UI проще при одном.
* `SUBSCRIPTION_HWID` сейчас константа `<HWID-REDACTED>`. При выносе в UCI
  надо решить, остаётся ли она значением по умолчанию или каждый роутер
  должен получать свой.
* Нужен ли фиктивный узел вместо ошибки, как у v2. У podkop роль другая: он
  не отдаёт подписку клиенту, а правит конфиг, и там уже есть `on_empty`.
